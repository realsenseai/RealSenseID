# RealSenseID STM32 Demo

Face authentication demo using an **STM32F407G-Discovery** board and an Intel **RealSenseID F500** module, communicating over UART.

> **Scope:** This sample targets the **STM32F407VGT6** specifically. The ST HAL and CMSIS trees are **not vendored** in this repo — they are regenerated from `stm-discovery-config.ioc` by STM32CubeMX/CubeIDE on first build (see step 4 below). Targeting a different board means opening the `.ioc`, changing the MCU, and regenerating.

## Hardware Requirements

- STM32F407G-Discovery board (STM32F407VGT6)
- Intel RealSenseID F500 module
- USB-TTL adapter (3.3V) for debug console
- Jumper wires

## Pin Connections

| Function | STM32 Pin | Direction | Connect To |
|---|---|---|---|
| **Device TX** | PA2 (USART2 TX) | STM32 → F500 | F500 RX (CDC UART) |
| **Device RX** | PA3 (USART2 RX) | F500 → STM32 | F500 TX (CDC UART) |
| **Console TX** | PD8 (USART3 TX) | STM32 → PC | USB-TTL RX |
| **Console RX** | PB11 (USART3 RX) | PC → STM32 | USB-TTL TX |
| **GND** | GND | — | Common ground (F500 + USB-TTL) |

Both UARTs run at **115200 baud, 8N1**.

## Build & Flash

This repo commits only the 8 files that contain real work: the `.ioc` (CubeMX source of truth), `main.c` and `stm32f4xx_it.c` (user code), the customized IDE project files, README, and `.gitignore`. Everything else — the entire `Drivers/` tree, the CubeMX-generated headers, `stm32f4xx_hal_msp.c`, `system_stm32f4xx.c`, `syscalls.c`/`sysmem.c`, `startup_stm32f407vgtx.s`, and the two `.ld` linker scripts — is regenerated by STM32CubeMX on first build. So the first build has an extra step:

1. Keep this sample inside the `rsid-device` repo — the build relies on relative paths to `Core/` and the sibling `../../src/` (embedded SDK sources).
2. Install **STM32CubeIDE 1.16+** (bundles CubeMX). Download: https://www.st.com/en/development-tools/stm32cubeide.html
3. **File → Import → Existing Projects into Workspace** → browse to the `STM32CubeIDE/` subdirectory. Import the `stm-discovery-config` project.
4. **Generate code from the .ioc** (one-time, and after any `.ioc` change):
   - Open `stm-discovery-config.ioc` in CubeMX view (double-click it or right-click → Open With → STM32CubeMX).
   - **Project → Generate Code** (Alt+K), or Ctrl+S on the `.ioc` view.
   - This (re)creates: `Drivers/CMSIS/`, `Drivers/STM32F4xx_HAL_Driver/`, `Core/Inc/{main.h, stm32f4xx_hal_conf.h, stm32f4xx_it.h}`, `Core/Src/{stm32f4xx_hal_msp.c, system_stm32f4xx.c}`, `STM32CubeIDE/Application/{Startup/startup_stm32f407vgtx.s, User/Core/{syscalls.c, sysmem.c}}`, and `STM32CubeIDE/STM32F407VGTX_{FLASH,RAM}.ld`. All of these are in `.gitignore`.
   - The USER CODE sections in `main.c` and `stm32f4xx_it.c` are preserved across regen — our app logic stays intact.
5. **Project → Build All** (Ctrl+B).
6. **Run → Debug** to flash and start debugging.

## Usage

Connect a serial terminal (PuTTY, minicom, etc.) to the USB-TTL adapter at **115200 baud**. On reset you'll see:

```
=== RealSenseID STM32 Demo ===
Device UART initialized
Type 'help' for commands
>
```

### Commands

| Command | Description |
|---|---|
| `p` / `ping` | Ping the device |
| `v` / `version` | Query firmware version |
| `a` / `auth` | Authenticate once |
| `l` / `loop` | Continuous auth loop (blue button to cancel) |
| `e <name>` | Enroll a new user |
| `r <name>` | Remove a user |
| `ra` / `remove-all` | Remove all enrolled users |
| `u` / `users` | Query enrolled user count |
| `sn` / `serial` | Query device serial number |
| `c` / `config` | Query device configuration |
| `reboot` | Reboot the device |

### F500 CDC UART Note

The F500 debug/command UART (CDC) has its TX channel disabled by default. The firmware automatically sends `init 1` on startup to enable bidirectional communication. If you reset only the F500 module (not the STM32), you may need to power-cycle or type `reboot` and wait for the auto-init sequence.

## LED Indicators

- **Green (LD4/PD12)** — Authentication or ping succeeded
- **Red (LD5/PD14)** — Authentication or ping failed
- **Orange (LD3/PD13)** — USART3 RX activity

## SDK Files

The RealSenseID embedded SDK is referenced directly from the sibling directory `../../src/` — no vendored copy lives inside this sample. The STM32CubeIDE project pulls the `.c` files in via linked resources (`STM32CubeIDE/.project`) and adds `../../src/` to the C include path (`STM32CubeIDE/.cproject`). Rebuilding the sample always picks up the current SDK next to it.
